# ADR-0065: Context Use in Generic Owned Replies

- Status: Accepted design for the explicitly continued Character iteration; V37 behavior remains unaccepted
- Date: 2026-10-06
- Authority: the user's request to address habitual recap and echo while retaining useful summaries
- Supersedes: ADR-0047/0049 only for the opt-in V37 movement description in the generic scope below;
  ADR-0058 remains the selection baseline and ADR-0052's news/care guidance is retained
- Related: ADR-0045, ADR-0048, ADR-0050, ADR-0051, ADR-0062, ADR-0064

## Evidence and bounded hypothesis

The recap diagnosis records
sampled evaluative restatement on ordinary `owned_response` turns. The same generic route also
produced substantive advice, so it does not deterministically require recap. The active peer
renderer already contains the global own-contribution and anti-echo principle. Its cognition
boundary requires the current meaning, not an exhaustive list of user facts to repeat.

Generic `respond/current_exchange` receives a broad movement description, while the goal-local
news and care clarifications do not apply to the criticized ordinary samples. This identifies
a small realization seam, not a proven cause of the prose. The withdrawn drive-line proposal
is not revived: the finite 800-assembly function audit
found no different-drive projection collisions in its defined comparisons. Existing manner,
personality, value and initiative guidance already carries part of the selected function.

V37 tests one hypothesis: distinguishing shared premises from Satori's own situated reply in
the generic movement description may reduce habitual reformulation without suppressing useful
context use. This is a realization and salience hypothesis. It adds no newly selected argument,
proposition or semantic interpretation before generation, and does not claim to repair missing
appraisal context or emotional attribution.

## Decision

Introduce opt-in policy V37 using V35's behavior principles and selection. In the existing sole
peer block, replace the existing movement line only when all of these typed conditions hold:

- agency status is `applied`;
- delivery goal is `owned_response`;
- agency act is `respond`;
- agency subject is `current_exchange`.

The replacement distinguishes supplied context as premises for Satori's own reaction or thought
from facts that must appear in the reply. It permits using those premises to make the selected
reply meaningful, rather than treating their reformulation as the default way to answer.
The contribution remains within the already frozen act, subject, initiative and lead. A short
situated reaction can be sufficient; a new fact, lasting position, question, advice, disagreement,
topic or visible emotion is not required. This creates neither a two-part response template nor
an additional personal afterword.

The same wording explicitly preserves repetition when it performs the requested or necessary
work: a summary, quotation, argument, calculation, reasoning step, clarification or check of
understanding. A requested recap remains valid even when the existing `REQUEST`/`QUESTION`
grammar does not recognize its wording. No new summary detector, cue expansion, keyword rule,
overlap threshold or semantic judge is introduced. The foreground generator realizes this
distinction using the already supplied current input and eligible context.

This is one replacement at the existing movement line. It does not append another global recap
ban, restore the withdrawn drive line or add a second expression block. All other peer guidance,
including complete cognition support, grounding, selected initiative, pressure, authoritative
personality/value/affect/relationship projections and news/care permissions, is retained.

## Isolation and compatibility

V37 remains opt-in. Default runtime stays V35 and the previous-exchange appraisal setting stays
off. ADR-0064 remains a separate candidate; its frozen API plan is not modified or repurposed.
Existing V36 plans, grants, blind artifacts and historical samples are also unchanged.

V37 reuses agency schema 2 and manifest schema 18 as supported protocol structures, with
`prior_conversational_cue=None`. V36's cue projection, selection and expression behavior is
enabled only for policy V36. Schema reuse must not silently activate that second intervention
on V37. V37's selected agency fields retain V35 semantics apart from the declared protocol
schema. V35 and V36 historical provider requests and native parameters remain reproducible.
Delivery/presence/cognition protocols and persistent schemas are unchanged.

Fallback and other movements retain their existing rendering. In particular, relational repair
or disclosure that also uses `owned_response` is outside the act/subject scope above. Existing
safety, listening, correction, repetition, repair, guardedness, direct task completeness and stop
priorities remain authoritative. The generic wording cannot expand the selected continuation
or treat an unclear premise as a known fact, motive, cause, memory or durable self position.

No provider/model, generation cap, temperature policy, source-admission permission, persistent
owner, state formula, migration, repository or writer changes. Normal foreground turns still
use one call. The same ten-reason validator and shared max-one retry remain; retry preserves
the selected movement and authoritative tentative affect/evidence. Generated output is committed
without rewriting and gains no new authority about self or relationships. No raw chain-of-thought,
phrase bank, new model judge or background task is introduced.

## Verification and decision gate

Freeze historical V35 and V36 request/native-parameter evidence before implementation. Verify
that V37 changes only the eligible movement line, version metadata and declared protocol schema;
all other assembled sections, completed cognition obligations, selection fields and native
parameters remain equivalent. Verify exact V35/V36 historical bytes and V35 default composition.
Explicitly check that V37 cannot select or render the V36 cue behavior.

The versioned deterministic corpus must include ordinary news and observations, a simple short
acknowledgement, requested summaries with recognized and unrecognized task wording, quotation,
useful premise repetition inside reasoning, clarification and understanding checks. Include
requests to examine a topic, mixed news/tasks, factual work, canonical positions/interests,
listen, correction, repair and stop. Cross relevant neutral/loaded affect and
fresh/established/strained/unknown relationships without prescribing desired reply text.

Check actual request inclusion/exclusion, one complete cognition boundary, protected precedence,
same-interaction retry, commit/replay/restart/failure, existing source receipts and absence of new
owner writes or calls. Synthetic responses can prove commitment and control flow, not that a
real response adds an appropriate contribution or recognizes a legitimate summary request.

Run the required rebuilt noneditable Foundation workflow and applicable real local Character
matrix, preserving every failed gate, sampled reply and timing. Parallel Foundations changes
remain outside this iteration and must not be reset or delayed to manufacture a global pass.
Local provider samples establish runtime evidence; they do not establish target character quality.

A controlled target-API comparison requires its own inspectable frozen source/input/state/model/
parameter plan, fresh explicit spending grant and one-shot claim. Hold appraisal context off and
exclude V36 cue behavior in both arms. Compare complete ordinary replies and protected controls
with identical initial conditions, retain failures and missing cells, and freeze human feedback
before disclosing assignments. Assess whether repeated material serves a conversational or task
purpose, whether the reply contributes appropriately, and whether it feels like Satori. Shorter
length, lower lexical overlap, a question mark or an added opinion alone is not success.

Habitual recap, semantic summary fulfillment and Character acceptance remain open. This design
does not require every reply to add novelty or display character. Checkpoint 14.3 Phase A remains
active; no later Character phase, Stage 15, persistent unfinished threads or external actions
are opened, and parallel Foundations continues independently.
