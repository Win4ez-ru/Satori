# ADR-0067: Bounded Current Position Before Expression

- Status: Accepted design for the explicitly continued Character iteration; behavior unaccepted
- Date: 2026-10-07
- Authority: the user's continuation after restoring the original Notion/product direction
- Supersedes: ADR-0045 only for the optional extra semantic operation after compatibility and
  before expression; the agency ordering and all persistent ownership remain unchanged
- Related: ADR-0057, ADR-0058, ADR-0065 and the Character direction review of 2026-10-06

## Evidence and hypothesis

The human V35/V37 review still criticizes ordinary replies as paraphrase. Requested-summary and
calculation controls do not demonstrate the independent character described in Notion and the
product constitution. Ordinary agency selects a movement; cognition `InternalPosition` mostly
contains an operational strategy. A specific current judgment remains the generator's choice.
This is a verified content boundary, not a proven cause of all weak replies.

Test one narrower hypothesis: a bounded concrete current position, formed from the same available
context before final prose, helps realize the already selected ordinary move. This iteration does
not test choosing agency from that position, fix affect sensitivity, change relationship appraisal
or implement future calls/calendar/tools.

## Decision

Add independent `conversation_current_position_enabled=false`. The candidate uses exactly the
V35 control, with previous-exchange appraisal off. V36/V37 and older policies cannot silently
inherit it. All disabled requests and foreground settings retain their existing behavior.

The candidate ordering is:

```text
existing owner reads, tentative affect, agency and completed cognition compatibility
→ existing immutable generation request and complete source-input receipt
→ for an eligible ordinary move, one explicit current-position proposal operation
→ strict application validation: none or one bounded provisional judgment
→ same selected agency/cognition plus marked proposal data
→ existing foreground generation and canonical finalization
```

Eligibility is applied `owned_response/respond/current_exchange`, without current typed cognition
signals or repeated-input/repetition/frustration feedback. Protected task, question, safety,
listening, correction, repair, self-disclosure, stop and canonical-position routes retain their
selection. Existing intake is deliberately not expanded into a new semantic task classifier:
an unrecognized requested summary can still enter the generic route. The proposal and realization
instructions must preserve such work and allow `none`, without a compulsory personal afterword.

The semantic operation reuses the foreground `ConversationProvider` port/model with a separately
visible output ceiling of 384 and temperature 0. It receives the already assembled immutable
request, explicit allowed reference IDs and trusted operation/schema instructions. This is one
additional call on eligible turns, not an inner-monologue loop or a second model judge.
The existing foreground cap/temperature remain unchanged. No format retry is added.

The strict frozen proposal is `none` or `view`. A view contains one focus, one short `current_take`,
one or two unique reachable support refs and `low` or `material` uncertainty. Text/collection
bounds and unsupported fields/refs are checked deterministically. A none outcome contains no
content or refs. Schema/source reachability do not prove semantic truth or character quality.
The operation asks for a concise result, never raw chain-of-thought or a draft of the full reply.

## Trust, lifetime and failures

The current position is provisional cognitive data. It is not a canonical Satori position,
personality, emotion, relationship update, permission or new user event. It has no repository,
writer or independent persistent lifetime. Source identifiers are references, not authority to
invent facts, biography, emotions or durable preferences. Existing grounded canonical positions
and uncertainty retain precedence over this proposal.

The validated datum is serialized in a distinct USER-role envelope before the existing final
peer DEVELOPER block and exact current canonical user input. The mandatory DEVELOPER/USER tail
remains intact for the existing retry. That wire role does not create a canonical user message
or fresh evidence.
One instruction is integrated into the existing single peer block; no second personality card
or phrase bank is added. The final generator uses the datum only within the frozen act, subject,
initiative, factual scope and complete cognition obligations. Foreground text is not rewritten.

The same complete actual-input receipt, including uncited sources, is admitted freshly before
both provider calls and checked by existing finalization. A proposal citing fewer refs does not
shrink its dependencies. None, invalid and provider-unavailable outcomes retain the full footprint.
Typed ordinary provider failure or invalid JSON/schema yields the original foreground request;
`SourcePolicyError` and unexpected contract failures fail the whole interaction. There is no
automatic semantic retry. Existing foreground max-one validator retry reuses the frozen datum
and sources, and never repeats the proposal operation. Completed replay performs neither call.

The existing character budget retains its trusted-context meaning. Preflight counts original
SYSTEM/DEVELOPER text and the extra semantic instruction before any optional I/O. Foreground
attachment counts original trusted text, the added peer instruction and the single bounded new
datum; pre-existing USER/ASSISTANT history is not newly charged to this budget. Neither operation
raises the configured cap. A known candidate overflow gives `skipped/context_budget` and the
unchanged foreground request, retaining any already consumed numeric proposal usage. Other
unexpected contract errors remain fatal.

## Metadata and compatibility

Fresh enabled turns use manifest 19 with current-position schema 1, closed status/reason,
ground refs and uncertainty. Only an applied datum adds `current_position_data`. No proposal text
enters manifest, normal logs, persistent state or raw reasoning storage. Usage/provider metrics
and proposal latency are reported separately from foreground generation. Failed operations retain
available numeric usage without fabricating missing counts. Replay may omit transient metadata;
it cannot recreate a position or make it canonical.

No database migration, owner contract, seed, category map, affect decay, relationship evidence,
provider adapter or ten-reason validator change. Prior frozen plans, grants, samples and maps are
untouched. Old paid authorization cannot authorize the candidate's additional call.
Parallel Foundations continues independently.

## Verification and decision gate

Tests cover strict schema/refs/roles/bounds, none/invalid/unavailable, legacy disabled bytes,
protected routes, operation order, actual source admission, exclusion between calls and before
commit, failure/replay/retry, independent counterparty context and persistent-owner parity.
Deterministic proposals establish content transfer and isolation only. State contrasts inspect
actual operation inputs and resulting realization data; they do not prescribe an offended phrase,
force disagreement or declare an unchanged act a failure.

Run the rebuilt Foundation workflow in an isolated snapshot and required applicable native
Character/gender diagnostics. Preserve every failure and distinguish native runtime evidence
from target-API semantic quality. Freeze a small novel multi-turn target comparison, explicit
two-operation budget and source/state/model/cap plan before requesting a fresh one-shot grant.
Evaluate independent contribution, grounded initiative, continuity after events and repair, and
recognizable Satori across the dialogue. Reject decorative aphorisms, relocated recap and
schema-valid hallucinations. Neither technical completion nor a preferred pair accepts Character.
