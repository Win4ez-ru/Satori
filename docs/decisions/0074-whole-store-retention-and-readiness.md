# ADR-0074: Whole-store Retention and Readiness Integration

- Status: Accepted; isolated macOS engineering gate passed
- Date: 2026-10-14
- Authority: explicit user continuation after the completed ADR-0072 vertical
- Related: ADR-0053/0057/0059/0060/0061/0063/0066/0068/0070/0071/0072
- Supersedes: blanket retained-by-table classification and incomplete terminal-family routing in
  ADR-0059, only where the exact supported row/owner/material contract is proved. Historical
  preparation-v1, all six action formats, owner mutation and numerical policies remain unchanged.

## Context

Six closed body actions share one approved floor/head and exact main material proofs. The current
inventory does not consume all of them: terminal Reflection, paired Appraisal explanations and
identity-owned checkpoint reasons can remain content or opaque review routes after actual NULL.
Many decision/history tables are retained by table name although scalar codes, structured values
or owner references may be unsupported legacy data. A successful parse, numeric value, field name
or familiar event is not a retained-data policy.

Existing root routes describe content/numerical/reference facets. One row may legitimately occur
in several facets. Summing them as installation-wide row coverage would double-count. The original
preparation digest also does not bind the current body head and is not a new readiness certificate.

## Decision

Open **14.4.2i — Whole-store Retention & Readiness Integration**. Reuse the existing 15-owner
registry, inventory read transaction, trusted installation barrier, validators and material indices.
There is no new writer, ledger, body action, source graph, migration or persistent readiness state.

### Distinct coverage and readiness

Every logical `(table, primary key)` in the exact admitted current main database receives exactly
one supported version-one classification:

1. `UNKNOWN` when any required carrier, version, closed code, owner/reference/scope or provenance
   proof is unsupported or absent.
2. `owned_content` when the owner/representation is proved and at least one available body remains.
3. `supported_retained` when only explicitly supported structural/numerical material or proved
   terminal representation remains.

Numeric history, structural references and terminal bodies are separate facets. Their counts are
not added to the three-class partition. All tables, including empty tables, have one registry owner;
the aggregate covers all 15 owners and partition totals equal the actual bounded census count.

Complete classification can coexist with remaining owned content. It is neither whole-root logical
completion, physical erasure, anonymity, causal source completeness nor authenticated permission.
An identity-scoped whole-store report does not fabricate a canonical USER root or counterparty.
Existing selected-root assessments retain their independent canonical/counterparty proof and affected
closure. Their historical facet counts and preparation-v1 serialization keep their meaning.

### Admission and single-census proof

The new standalone inventory proves exact schema and requested identity/installation/lineage before
private counts or content reads. It performs fresh source/erasure/body mirror verification in the
same read transaction before the protected census, even if the supplied runtime lacks a callback.
Pending, missing/replaced floor or old-main state denies safely without auto-enrollment, repair,
provider construction or protected coverage output.

After one bounded `_load_store`, one transaction-local retention context shares indexed material,
historical provenance, audit classification and closed row contracts across all owners and all
selected roots. It is bound to that store/schema/snapshot; caller-supplied terminal flags, copied
ACKs and cross-store cached contexts are not authority. Whole-head proof checks exact ordered action
bindings, trusted head digest, all six scopes and actual owner NULL/markers/retained material.
Existing owner validators remain authoritative; a historical context alone is not head admission.

Legacy intent preparation/resume has a separate explicit `for_owner_assessment` factory. It can
inspect bounded available/pending representations while restoring the existing intent-before-body
acknowledgment order. It grants no current-head or terminal badge when the whole head is pending;
already terminal rows remain conservatively UNKNOWN. Where NULL canonical roots require historical
attribution, the coordinator supplies the actual floor-approved ordered actions under its held
lease, and the factory checks their exact trusted digest/scope. A copied main prefix or invented
snapshot is not authority. This operator assessment cannot be used by the new current-readiness
adapter, which always performs strict fresh mirror admission. Neither path auto-reconciles content.

Terminal Reflection requires its complete immutable parent/source/attempt/outcome contract.
Terminal Appraisal requires both explanation copies, exact actual-input closure and numerical
material. Terminal checkpoint reasons require exact identity/receipt/checkpoint/trait/revision
closure. Initial self names and value descriptions are declared owned content unless a separate
canonical seed contract is proved; they are not metadata merely because their tables are initial.

Closed scalar/structured contracts check exact row fields, versions/codes/status relationships,
finite bounded numbers, strict bounded duplicate-free JSON and actual indexed owner/reference
joins. Opaque identifier/provider/model/policy labels are retained only in their declared bounded
identifier roles; no provider-specific allowlist is introduced. Retained IDs/hashes remain sensitive.
Missing legacy audit bindings and unsupported or prose-bearing scalar values remain UNKNOWN.
No legacy provenance is guessed, sealed or backfilled and no row is rewritten for classification.
Retention proof never makes excluded, archived or historical data fresh learning evidence.

Embedding vectors use a separate declared field-role contract, aligned with the existing
provider-neutral vector semantics and configured dimension bounds: 1–8192 components, exact
dimension, finite native numbers excluding booleans, and nonzero vector norm. Its bounded JSON
representation permits 262,144 bytes, including ordinary 768/1536-dimensional vectors. Generic
JSON collection/depth/node limits remain unchanged; the vector role introduces no provider
allowlist or arbitrary numerical-magnitude threshold. Unsupported representations remain UNKNOWN.

Existing 100,000-row, 64 MiB input and approved-head bounds remain. A classifier-local deterministic
one-million-work budget charges indexing, classification and repeated reference walks; existing
owner validator budgets remain separate admission limits. There is no per-row whole-store scan,
unbounded JSON walk, protected global cache, universal scale or linear-time claim.

### Contracts, controls and freshness

New immutable application contracts provide identity-scoped `state retention --status` and
`--check` with expected source generation, erasure/body revisions and a reviewed SHA-256 digest.
Output has only supported table/owner names, safe class/facet/reason counts and opaque digests.
It never renders raw labels/codes from unsupported rows, private row/descendant IDs, JSON, body
prose or exception text. Explicit trusted identity/installation/floor/lineage scope remains metadata.

The separate readiness digest binds policy version, identity/installation/floor/lineage, source
generation, erasure/body revisions and head, exact schema, entire logical store and exact private
row classification. Counts alone cannot hide a changed row set. A check is a fresh snapshot match,
not a reservation or execution grant. Unknown coverage is partial/blocked and remaining content is
explicit even with complete classification.

Root routing consumes the same proved decisions for completed terminal families and unsupported
metadata. Existing preparation refresh uses its normal append/idempotency path. Original receipts,
preparation-v1 decoder/fields/hash, action bytes/material hashes, audit bindings, numerical trajectory,
budget spend and Character behavior are unchanged. Read controls never reconcile or append receipts.

### Engineering gate and residuals

- Exact disjoint row totals and all 15 owners; live content, all six terminal families, numerical
  facets and current/legacy/foreign/malformed/unsupported scalar/duplicate-JSON cases.
- Actual available embedding rows at configured working dimensions and bounded maximum; invalid
  vector numbers, zero norm, dimensions, bytes and work capacity fail closed.
- Scope/admission before census, missing callbacks, pending/copied ACK/tampered material, bounded
  work/bytes/rows, same-generation and body-head-only freshness drift and no cross-store proof reuse.
- Existing root/preparation integration, historical serialization/hash parity and unchanged rows,
  floor/binding/lock bytes on repeated read controls.
- Actual managed six-action/private CLI/restart/archive scenario with independent live content,
  explicit UNKNOWN mutations and explicit resume; zero real/paid providers.
- Rebuilt isolated unfiltered Foundation, exact installed/source parity, fresh migration/bootstrap,
  independent review, local cost and documentation.

All results retain `physical_erasure=false`, `execution_authorized=false` and explicitly unassessed
external surfaces. Numerical influence, sensitive IDs/hashes, legacy UNKNOWN, SQLite free pages/WAL,
archives/exports, OS/provider copies, whole-floor rollback, physical cleanup, authenticated access,
encryption/key recovery, Linux and whole-14.4 acceptance remain separate gates. Character tuning,
experiments, 14.4.3 and Stage 15 are not opened.
