# ADR 0049: Understated contextual expression

- Status: Superseded in part by ADR-0050 for active ordinary-initiative realization
- Date: 2026-09-28
- Supersedes: ADR-0047 only for active provider realization; ADR-0048 selective casual coverage
  and every persistent-state, cognition, agency and safety boundary remain in force

## Context

In diagnostic 4 the user preferred A (V29) to B (V27), while rejecting overall Satori recognition.
The user then explicitly liked V29's brief topic closure, reading slight hurt and a tsundere edge
in its restraint. The assistant's claim that this reply lacked character was incorrect. This
specific positive example must not be expanded with warmth, advice or another question merely
to make character more explicit. The user's interpretation is style feedback, not evidence that
the canonical affect state contained offense.

V29 already permits ordinary, selective conversation. Inspection nevertheless found a sequential
rendering instruction: make an owned move first, then deliver cognition obligations. Together
with self-disclosure and uncertainty guidance, this can invite a second explanatory passage.
It is a plausible expression pressure, not a proven cause of the user's overall preference.
The user authorized continuing calibration after this correction.

## Decision

Introduce policy V30 as the implementation candidate. Preserve V29 policy, selected agency acts,
delivery/presence/manifest schemas 5/3/17, cognition intent/template versions 2/3, source evidence,
request limits, temperature, validation and max-one retry behavior. No selector or owner changes.

Version the existing single peer renderer rather than append a second personality block:

- Honor the selected lead order within one reply; cognition obligations do not require a second
  explanatory passage or personal afterword. Render the full typed cognition boundary unchanged.
- On ordinary interest/affect questions, let traits guide word choice and current engagement.
  A general curiosity trait is not a current concrete interest or an instruction to list traits.
  Direct requests to describe character, state, identity, memory or capability retain factual
  answers; selective casual coverage never suppresses explicit complete task requests.
- Scale disagreement to the actual objection and identify the actual uncertainty. General
  exposition is optional unless requested or necessary for a complete, accurate answer.
- Ordinary care can be direct without a general lesson, permission to feel or an unsolicited plan.
- A short, restrained closure is complete. Do not automatically add warmth, reconciliation,
  self-explanation or a question; do not invent hurt, demand concession or continue a stopped topic.

Existing relationship, affect, distress, listening, repair, grounding and factual self boundaries
remain authoritative. No new emotion label, permanent tsundere mode, phrase bank, seed hobby,
prose example, model judge, response rewrite, semantic retry or provider call is introduced.
The approved closure is used only as mock transport output in a commit/replay test, not as a
provider instruction or acceptance target. Human recognition remains separate from technical tests.

## Verification and gate

Freeze 42 pre-change V29 public request/parameter hashes and a baseline source archive. The
versioned V30 corpus crosses relationship, affect, casual/explicit requests, closure and its
negation/question variants. Confirm unchanged typed decisions and parameters, complete cognition
boundary, historical V29 bytes, historical V28 tests, default composition, max-one identical-block
retry, fallback and exact response commitment/replay with unchanged self.

Run Foundation checks and the applicable local character/dialogue regression matrix: before/after
exact production dialogue, three fresh candidate sessions, 30-turn coherence, activities,
relationship conditions, identity/independence and real CLI gender/identity. Retain actual public
replies and all failures with usage/timing metadata, without raw prompts or retrieved context.
Local Qwen results do not establish target-model character acceptance. A later paid comparison
requires a new frozen plan and separately approved call/cost ceiling. No consumed claim is reused.
Checkpoint 14.3 Phase A remains active; V10 remains the accepted baseline and later stages closed.
