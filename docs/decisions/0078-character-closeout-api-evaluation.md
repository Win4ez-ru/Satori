# ADR-0078: Bounded Character Closeout API Evaluation

- Status: Accepted bounded evaluation scope; one paid invocation consumed, Character acceptance open
- Date: 2026-10-16
- Authority: user approves the closeout plan and requests adapters, offline checks and an exact total budget, explicitly without an API run
- Supersedes: none; production cloud foreground restriction remains in force
- Related: ADR-0003, ADR-0004, ADR-0031, ADR-0032, ADR-0044, ADR-0053, ADR-0057, ADR-0077

## Problem and hypothesis

The consolidated Character review finds recognizable real behavior unaccepted. Recent neutral
appraisal samples and isolated repair classifiers cannot assess the whole state-to-expression
path. Production cloud routing covers conversation only; using a cloud reply with local appraisal
would leave the suspected semantic boundary dependent on Ollama.

A bounded evaluation of the existing owners with actual API proposals can locate the dominant
behavioral failure without adding another character mechanism. Successful offline wiring is
preparation evidence, not evidence of model understanding or acceptable personality.

## Evaluation boundary

Use test-only bridges for the existing affect, relationship, episodic formation, semantic formation
and embedding ports. Reuse the current request serialization and proposal validation where
possible. The existing owners retain proposal admission, bounds, transactions, source receipts
and audit. No bridge writes domain state, changes production configuration, creates a new owner
or rewrites generated prose. Foreground uses the existing OpenAI conversation adapter.

Freeze V35 with all four later experimental flags disabled. This run is a diagnostic baseline;
it contains no newly optimized personality candidate and cannot establish a before/after winner.
Preserve the previous target model `gpt-5.6-terra`, reasoning `none`, standard service tier and
stateless Responses requests. Semantic embeddings use `text-embedding-3-small` with a declared
compatible 768-dimensional evaluation space. Providers are explicitly evaluation-only; the
production cloud background prohibition is neither removed nor bypassed in normal composition.

Twenty independent scenarios contain 90 base user turns. The additional continuous mode uses
30 turns and two actual process restarts. Scenario 19 adds twelve profile/counterparty probe turns:
132 scheduled user turns in total. Dependencies reuse actual completed owner snapshots rather
than invented assistant prefixes. All data is authored test material, not real user biography.

Fresh/familiar/strained contrast setup uses canonical test-user roots and authored typed proposals
through the existing Relationship owner. These are controlled profile fixtures, not evidence of
natural relationship formation by the API. Actual appraisal and post-response updates on the
132 probes, especially the continuous trajectory, are reported separately. No missing memory
is hand-inserted: the memory scenarios require actual formation and source roots.

## Calls, money and interruption

Freeze every possible operation, model, output limit and input-byte ceiling before execution.
Each user turn allows one affect, one relationship, one episode, at most one semantic formation,
one retrieval embedding and one index embedding operation. Foreground retains the existing
shared maximum of one typed validator retry. No transport retries, refill, extra samples, paid
judge or automatic local-model substitution are allowed.

Use integer monetary arithmetic and a durable reservation before any transport. Reserve the
worst applicable standard-context price including cache-write pricing. Unknown usage, refusal,
truncation, unexpected model/tier, malformed output or transport uncertainty stops subsequent
paid work; an uncertain reservation remains charged at its ceiling. A committed foreground reply
does not conceal a failed post-response operation. Optional owner skips remain explicit and do
not authorize another operation.

Bind the plan to corpus, source, tests, settings and tariff evidence. Preparation reads no API key
and performs no inference. A later execution requires a fresh explicit human grant for that
exact plan and total ceiling. A single campaign claim and persisted operation records prevent
repeating a completed or uncertain call across process restarts. Semantic branch choices are
bound to the actual preceding reply; no fabricated prefix, silent branch guess or new judge call
is permitted. Artifacts and synthetic dialogue stay private with restricted filesystem modes.

## Verification and acceptance

Offline tests exercise API envelopes, strict schemas, accounting, failure/stop paths, source
admission, actual owner commits, replay/isolation and restart without model transport. The full
Foundation toolchain is run after rebuilding the local package. The historical duplicate V33
fixture is restored to its explicit V33 and standalone test-only scope without deleting tests or
weakening assertions.

Record preparation and execution independently. All real scenarios remain NOT_RUN until the
freshly authorized invocation produces actual results. The human review criteria remain explicit;
transport success and relative preference cannot accept Character. Parallel Foundations continues
independently, and Stage 15 remains closed.
